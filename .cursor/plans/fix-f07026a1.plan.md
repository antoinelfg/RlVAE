### Implementation Steps

1) Verify RHMC posterior is active in the run

- Confirm that `experiment=rlvae_three_stage_long_rhmc_modular` yields `posterior_type: riemannian_rhmc` and that `SamplerManager` is used during Stage C model construction. If not, add an assert/log at model init time showing `posterior_type` and `sampler_manager.riemannian_rhmc_posterior.get_config()`.
- Add a one-line WandB/system log at first training step summarizing RHMC config in use to avoid silent misconfigs.

2) Implement RHMCKLDivergence with 3 estimators

- New file: `src/rlvae/models/components/rhmc_kl.py` with class `RHMCKLDivergence` exposing:
  - compute_mc(mu, log_var, z, rhmc_post): returns E[log q_RHMC(z|x) - log p(z)] using `rhmc_post._compute_log_posterior` and `rhmc_post._compute_log_prior`.
  - compute_jacobian(mu, log_var, z, rhmc_post, traj_info): adds optional log|det J| correction when we have per-step Jacobian estimates (off by default).
  - compute_bound(mu, log_var, z, rhmc_post): a conservative upper bound using Riemannian Gaussian surrogate at μ (existing Riemannian KL) as a fallback.
- All methods return a scalar loss (mean over batch). Include numerical guards, AMP-safe ops.

3) Wire KL into LossManager

- Add an instance of `RHMCKLDivergence` inside `LossManager`.
- Implement `compute_rhmc_kl_loss(...)` to select estimator by config/env:
  - env `RHMC_KL_MODE=mc|jac|bound` (default mc), and optional `RHMC_KL_JAC_USE=false`.
  - Compute `log_q` via RHMC posterior if not provided and performance permits. If provided via sampler, reuse.
  - Compute `log_p` using rhmc posterior `_compute_log_prior` (volume prior).
  - Return mean(log_q - log_p).

4) Augment RHMC posterior to optionally emit log_q and trajectory info

- Extend `sample_riemannian_rhmc_posterior(..., return_log_prob: bool=False, return_traj: bool=False)` to optionally return `(z, log_q, traj_info)`.
  - `traj_info` may include per-step z, rho, and any available divergence/Jacobian proxy if later enabled. Default to None to keep it lightweight.
  - Keep current defaults to preserve training speed.

5) Ensure training path passes RHMC context to LossManager

- In the model forward where we sample latents for Stage C training, make sure we:
  - Use `sampler_manager.sample_training(..., posterior_type='riemannian_rhmc')`.
  - Capture `rhmc_log_q` when available and pass both `rhmc_posterior` and `rhmc_log_q` into `LossManager.compute_total_loss` so the RHMC KL path is chosen.
- If the existing pipeline already does this, just ensure `rhmc_log_q` is populated when `RHMC_KL_MODE=mc`.

6) Fix enhanced_kl visualization to show correct KL components

- In `create_enhanced_kl_visualization`, after computing `z_posterior_flat`, also compute:
  - `log_q_post = rhmc_post._compute_log_posterior(z_posterior_flat, mu_flat, 0)`
  - `log_p_post = rhmc_post._compute_log_prior(z_posterior_flat)`
  - Display summary stats: mean KL, mean log_p, mean log_q in the caption textbox.
- Add a top-left annotation of RHMC config (alpha, steps, eps) actually used for clarity.
- Keep RNG isolation and caching behavior intact.

7) Config switches and safety

- Add Hydra/ENV flags to control KL estimator and whether to request `return_log_prob` from the RHMC sampler during training and viz:
  - hydra: `model.rhmc_kl_mode` with choices [mc, jac, bound].
  - env fallback: `RHMC_KL_MODE` for quick overrides.
- Default to MC for both training and viz. Keep RHMC steps 0 by default if stability is a concern; steps >0 can be enabled progressively.
