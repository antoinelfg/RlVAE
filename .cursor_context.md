# RlVAE Project Context for Cursor AI

This document provides comprehensive context for AI assistants working on the RlVAE (Riemannian Flow VAE) project. It contains everything needed to understand the architecture, codebase, and research goals.

## 🎯 Project Overview

**RlVAE** is a research framework for **Riemannian Flow Variational Autoencoders** applied to longitudinal data modeling. The framework implements advanced geometric deep learning techniques with modular, production-ready components.

### Core Research Focus
- **Riemannian Geometry in VAEs**: Learning latent spaces with Riemannian structure
- **Temporal Dynamics**: Modeling sequential/longitudinal data with geometric flows
- **Metric Learning**: Learning data-dependent Riemannian metrics for improved representations
- **Comparative Analysis**: Systematic comparison of geometric vs. standard VAE approaches

## 🏗️ Architecture Overview

### Two-Stage Training Pipeline
1. **Stage 1: Vanilla VAE + Metric Extraction**
   - Train standard VAE on data
   - Extract learned representations as Riemannian metric
   - Save encoder, decoder, and metric tensors
   - **Naming Convention**: `pipeline_stage1_vanilla_vae_{architecture}_ld{latent_dim}`

2. **Stage 2: RlVAE Training**
   - Load pretrained components from Stage 1
   - Train RlVAE with geometric constraints
   - Use extracted metric for Riemannian sampling
   - **Naming Convention**: `pipeline_stage2_rlvae_{architecture}_ld{latent_dim}`

### Core Models

#### 1. Modular Vanilla VAE (`src/models/modular_vanilla_vae.py`)
- **Purpose**: Stage 1 training for metric extraction
- **Architectures**: MLP, CNN, ResNet encoders/decoders
- **Key Features**: Modular components, Hydra configuration
- **Factory Functions**: `create_cnn_vanilla_vae()`, `create_resnet_vanilla_vae()`, `create_mlp_vanilla_vae()`

#### 2. Modular RlVAE (`src/models/modular_rlvae.py`)
- **Purpose**: Full Riemannian Flow VAE implementation
- **Key Features**: 100% modular architecture, configuration-driven
- **Components**: MetricTensor, FlowManager, LossManager, MetricLoader
- **Posterior Types**: `gaussian`, `iaf`, `riemannian_metric`

#### 3. Hybrid RlVAE (`src/models/hybrid_rlvae.py`)
- **Purpose**: Performance-optimized version (2x faster metric computations)
- **Use Case**: When you need original compatibility with speed improvements

#### 4. Standard RlVAE (`src/models/riemannian_flow_vae.py`)
- **Purpose**: Original implementation for baseline comparisons
- **Features**: Multiple sampling methods, flow management

### Modular Components (`src/models/components/`)

#### EncoderManager & DecoderManager
- **Purpose**: Plug-and-play architecture handling
- **Supported**: MLP, CNN, ResNet
- **Configuration**: Hydra-driven parameter management

#### MetricTensor (`metric_tensor.py`)
- **Purpose**: Optimized Riemannian metric computations
- **Performance**: 2x faster than legacy implementation
- **Features**: GPU acceleration, batch processing

#### FlowManager (`flow_manager.py`)
- **Purpose**: Normalizing flow management
- **Types**: Inverse Autoregressive Flows (IAF)
- **Features**: Temporal dynamics, log-determinant computation

#### LossManager (`loss_manager.py`)
- **Purpose**: Modular loss computation
- **Types**: Reconstruction, KL divergence, Riemannian KL, flow losses
- **Configuration**: Separate beta parameters for different loss components

#### MetricLoader (`metric_loader.py`)
- **Purpose**: Loading pretrained metrics from Stage 1
- **Features**: Path resolution, device management, validation

```
conf/
├── experiment/          # Experiment types
│   ├── global_vanilla_rlvae_pipeline.yaml  # Two-stage pipeline
│   ├── comparison_study.yaml               # Model comparisons
│   └── single_run.yaml                     # Single experiments
├── model/              # Model configurations
│   ├── vanilla_vae.yaml                   # Vanilla VAE
│   ├── mlp_rlvae.yaml                     # MLP RlVAE
│   ├── cnn_rlvae.yaml                     # CNN RlVAE
│   └── resnet_rlvae.yaml                  # ResNet RlVAE
├── training/           # Training configurations
│   ├── quick.yaml                         # Fast development (20 epochs)
│   ├── default.yaml                       # Standard training (100 epochs)
│   └── full_data.yaml                     # Production training (50 epochs)
├── sweep/              # Hyperparameter sweeps
│   ├── learning_rate_optimization.yaml    # LR/weight decay optimization
│   ├── architecture_optimization.yaml     # Architecture comparison
│   └── comprehensive_hyperparameter_sweep.yaml  # Full parameter space
└── visualization/      # Visualization levels
    ├── minimal.yaml                       # Basic plots only
    ├── standard.yaml                      # Balanced analysis
    ├── full.yaml                          # Comprehensive diagnostics
    ├── final_only.yaml                    # End-of-training only
    └── end_only.yaml                      # Disable during training
```

## 🚀 Hyperparameter Optimization System

### WandB Integration
- **Project**: `rlvae-hyperparameter-optimization`
- **Sweep Types**: Random, Grid, Bayesian optimization
- **Metrics**: `val_loss`, `reconstruction_loss`, `kl_loss`, `riemannian_kl`

### Sweep Configurations

#### 1. Learning Rate Optimization (`learning_rate_optimization.yaml`)
- **Focus**: Training dynamics optimization
- **Parameters**: `lr`, `weight_decay`, `batch_size`, `beta`, `riemannian_beta`
- **Runs**: 50 random samples
- **Early Termination**: Hyperband with eta=2

#### 2. Architecture Optimization (`architecture_optimization.yaml`)
- **Focus**: Model architecture comparison
- **Parameters**: `stage1_architecture`, `stage2_model`, `latent_dim`, `n_flows`
- **Method**: Grid search for systematic comparison
- **Architectures**: MLP, CNN, ResNet combinations

#### 3. Comprehensive Sweep (`comprehensive_hyperparameter_sweep.yaml`)
- **Focus**: Full parameter space optimization
- **Parameters**: All major hyperparameters across both stages
- **Runs**: 100 random samples
- **Features**: Early termination, concurrent execution

### SLURM Integration (`scripts/slurm/`)

#### Batch Scripts
- **`run_hyperparameter_sweep.sbatch`**: Standard 47-hour sweeps
- **`run_hyperparameter_sweep_short.sbatch`**: 4-hour test sweeps
- **`run_extended_sweep.sh`**: Unlimited duration via chunking
- **`run_experiment_rlvae.sbatch`**: Single experiment execution

#### Usage Patterns
```bash
# Run standard sweep
sbatch scripts/slurm/run_hyperparameter_sweep.sbatch learning_rate_optimization 4 20

# Multiple agents on same sweep
sbatch scripts/slurm/run_hyperparameter_sweep.sbatch comprehensive_hyperparameter_sweep 4 50
sbatch scripts/slurm/run_hyperparameter_sweep.sbatch comprehensive_hyperparameter_sweep 4 50
sbatch scripts/slurm/run_hyperparameter_sweep.sbatch comprehensive_hyperparameter_sweep 4 50
```

## 🚨 Common Issues & Solutions

### WandB Connection Issues
- **Timeout Errors**: Extended timeout to 300s in `run_experiment.py` and `run_sweep.py`
- **Parameter Validation**: Fixed parameter naming (no dots in WandB sweep configs)

### SLURM Issues
- **Time Limits**: GPU partition limited to 48 hours (not 72)
- **Module Loading**: Remove non-existent modules, use correct conda paths

### Memory Issues
- **Large Visualizations**: Use `max_sequences` parameter to limit memory usage
- **Batch Size**: Reduce batch size for large models or limited GPU memory

### Configuration Issues
- **Parameter Overrides**: Use dot notation for nested parameters
- **Missing Configs**: Check `conf/` directory structure and defaults
